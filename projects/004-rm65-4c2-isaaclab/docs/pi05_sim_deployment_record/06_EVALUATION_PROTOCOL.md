# 评测协议

## 目标

评测要回答的是：在冻结 checkpoint、控制器和成功条件后，pi0.5 是否能在未用于调参的 RM65-B + 4C2 仿真案例中稳定完成抓取、搬运和释放。

## 数据分区

| 分区 | 可否用于调参 | 当前用途 |
|---|---|---|
| 训练集 | 是 | pi0.5 LoRA 微调 |
| validation | 是 | 训练过程和离线检查 |
| 开发/诊断计划 | 是 | 阈值、监督器和失败定位 |
| 独立确认集 | 否 | 冻结方案后的最终门槛判断 |

一旦独立确认集的具体失败案例被用于补数据、修改控制器或选择 checkpoint，该集合就应退役为开发集；之后必须生成新的策略种子、仿真种子和场景组合做确认。

## 案例设计要求

- `case_id` 唯一；
- `policy_noise_seed` 唯一且为非负整数；
- `simulation_seed` 唯一且为非负整数；
- 开发集与确认集种子不得重叠；
- 同时覆盖 transfer angle、源位置偏移和提示词表达；
- 条件位于专家数据覆盖范围内时称为 held-out interpolation，超出范围时必须单独标为 extrapolation；
- 每次正式评测前冻结 checkpoint、归一化统计、控制器阈值和代码提交。

## 单案例成功条件

案例报告需满足所有有限性和 episode 合同检查，并通过以下任务指标：

| 指标 | 条件 |
|---|---:|
| 源到目标 XY 搬运距离 | `> 0.12 m` |
| 方块抬升高度 | `> 0.02 m` |
| 最终目标 XY 误差 | `< 0.05 m` |
| 最终目标三维位置误差 | `< 0.05 m` |
| 释放后漂移 | `< 0.02 m` |
| 释放验证 | `verified=true` |
| 状态有限性 | `all_states_finite=true` |

安全中止不能被算作成功。运行错误、超时和缺失报告必须与正常任务失败分开统计。

## 当前套件门槛

- 最少 20 个有效报告；
- 成功率至少 80%；
- 正式配置必须使用 120 个最大动作 chunk；
- 策略夹爪张开命令阈值 `0.12`；
- 真实夹爪反馈阈值 `0.20`；
- 释放候选需连续 2 个 chunk。

当前确认集恰好为 16/20，因此只说明通过当前门槛，不能说明已经有宽裕的鲁棒性余量。

## 重试政策

- 允许：策略服务启动失败、进程崩溃、报告没有产生等基础设施故障；
- 不允许：案例已经产生合法 `status=fail` 后重跑并挑选成功结果；
- 所有重试必须保留 attempt、return code、timeout 和日志路径；
- 复用历史报告时必须验证完整实验合同，而不是只看文件是否存在。

## 必须报告的分层

除了总体成功率，还必须报告：

- 按 transfer angle；
- 按 prompt；
- 按源位置偏移；
- 按失败阶段：未抓取、抬升不足、未到达、未释放、安全中止、基础设施错误；
- 推理延迟、动作 chunk 数和 GPU/运行资源（下一版报告补充）。

## 下一版统计要求

下一轮正式鲁棒性评测应至少使用 60 个全新案例，分成 3 个预先固定的 20-case panel。整体和每个关键分层都报告 Wilson 置信区间，避免将一次 16/20 的边界结果解读为稳定的 80%。
