# 下一阶段实验计划

## 目标

先确认当前 16/20 是否具有可重复性，再针对“未到达目标”做数据闭环。不要在同一轮同时更换 checkpoint、控制器阈值、视觉处理和评测分布，否则无法判断提升来源。

## 阶段 A：冻结当前方案，做 60-case 新种子鲁棒性评测

冻结项：

- checkpoint：`rm65_policy_window_v2_lora_30k/29999`；
- repo id：`local/rm65_sim_policy_train`；
- 策略夹爪阈值：`0.12`；
- 真实夹爪阈值：`0.20`；
- 最大动作 chunk：`120`；
- 释放候选连续数：`2`；
- 当前代码提交。

建立 A/B/C 三个 panel，每个 20 个案例，策略和仿真种子均与开发集、旧确认集及其他 panel 不重叠。每个 panel 平衡覆盖：

- transfer angle：`0.65 / 0.75 / 0.85 / 0.95 rad`；
- source offset：中心与 `±7.5 mm` 组合；
- 5 类提示词；
- 可选的轻微光照/相机扰动应单独标记，不能混入基准 panel 后不说明。

预注册判定：60 个案例完整后再统一查看总体结论；不得因某个 panel 结果不好而修改剩余 panel。

## 阶段 B：失败邻域诊断

对新评测失败逐项记录：

- 是否形成稳定双侧接触；
- 最大抬升和首次抬升 chunk；
- 最小目标距离及其 chunk；
- 是否发生绕路、停滞或反向移动；
- 夹爪命令与真实反馈的时间差；
- 安全中止原因；
- 同一物理初始状态重复运行的任务结果是否一致。

优先比较旧确认集薄弱项：0.85 rad 与 `place block on target platform`，但旧确认集不再作为新方案的最终确认集。

## 阶段 C：最小化数据闭环

仅针对确认的失败阶段收集专家纠正数据：

1. 抓取前姿态对齐；
2. 稳定闭合与抬升；
3. 从 0.85 rad 邻域搬运到目标；
4. `place block on target platform` 的语言变体；
5. 必要时加入渲染轻微扰动配对样本。

保持原始数据不变，新增数据使用独立 manifest 和版本号。训练 v3 时记录新旧样本比例，并先做离线/小规模开发集比较。

## 阶段 D：v3 独立确认

v3 只有在开发集显示提升且没有明显回退后，才生成一套全新 60-case 确认计划。v3 不得继续使用阶段 A 的 60 个案例作为“独立确认”。

## 停止条件

- 出现非有限状态或仿真越界趋势时，停止该批次并先处理安全问题；
- 失败集中在基础设施而不是模型时，不进入训练数据闭环；
- 新数据提高薄弱场景却显著损害原有简单场景时，不升级 checkpoint；
- 未完成全部预注册案例时，不宣布总体门槛通过。
