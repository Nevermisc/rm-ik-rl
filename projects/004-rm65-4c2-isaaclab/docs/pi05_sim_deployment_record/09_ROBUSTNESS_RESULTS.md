# 60-case 鲁棒性评测结果

## 结论

代码复核发现，首轮 51/60 中的 4 个 `unsafe_ik_branch_jump` 并不是 pi0.5 会执行的运动路径：程序进入闭环策略后会提前返回，但旧实现仍在策略启动前计算后续 scripted 放置轨迹。`c707b7d` 只跳过 pi0.5 模式下的无关预计算，scripted 模式的 0.75 rad 安全阈值保持不变。

按“每个受影响案例第一次真正进入 pi0.5”的审计口径，纠正后的主结果是 **54/60（90%）**。60 份报告齐全，全部为仿真执行，没有真实机械臂命令。总体 95% Wilson 区间为 **79.9%–95.3%**，下界仍略低于 80%。

随后用相同 checkpoint、策略 seed 和仿真 seed 做正式复现，得到 **55/60（91.7%）**，Wilson 区间 **81.9%–96.4%**。但 `robust_042` 从首次执行失败翻转为复现成功，因此 55/60 是重复性诊断结果，不替代 54/60 的首次执行主结果。

## 重复性审计

4 个修复案例各执行两次。对比结果：

| 检查 | 一致数 |
|---|---:|
| 初始关节状态哈希 | 4/4 |
| 初始夹爪状态哈希 | 4/4 |
| 第 0 块显式噪声哈希 | 4/4 |
| 外部相机首帧哈希 | 0/4 |
| 腕部相机首帧哈希 | 0/4 |
| 第 0 块原始动作哈希 | 0/4 |
| 最终 pass/fail 状态 | 3/4 |

分歧从首帧视觉输入开始，不是策略 noise seed 或初始关节状态错误。当前可以声明“显式策略噪声可复核”，不能声明“闭环端到端确定”。

随后新增了精确观测采集：在不增加渲染 tick 的前提下，把第 0 个 chunk 实际发送给策略的 RGB 数组暂存到控制结束，再保存为无损 PNG。两次新诊断的 PNG 解码哈希均与报告哈希严格一致。经过 OpenPI 自身 `resize_with_pad(224,224)` 后，外部图只有 108 个像素、腕部图 330 个像素不同，最大差值都只有 1；第一个执行动作块的最大目标差为 `4.51e-4`。两次最终都失败，但一次抬升仅 0.43 mm，另一次抬升 34.81 mm 并到达目标附近，说明微小初始动作差会在闭环中被显著放大。

## 门禁与证据口径

1. 评测门禁仍要求至少 20 例、全部计划报告存在、成功率至少 80%；
2. 缺报告和基础设施失败不能被忽略；
3. 合法模型失败不重跑择优；
4. 本次四个替换是因为旧报告根本没有进入策略，主结果使用各自第一次真实策略执行；
5. 正式复现中的状态翻转单独记录，不用于回写主结果；
6. `simulation_only=true`、`real_robot_command_sent=false`，真机门禁继续关闭。

## 20×3 重复性矩阵

冻结 20 个条件、checkpoint、控制器参数和双 seed，各运行 3 次。60/60 报告有效，三轮成功事件分别为 17/20、16/20、16/20；这些重复事件不是新的独立性能样本。

| 指标 | 结果 | 门槛 |
|---|---:|---:|
| 状态一致条件 | 17/20（85%） | ≥95% |
| 翻转条件 | 3（008、028、042） | ≤1 |
| 初始关节/夹爪/noise 哈希一致 | 20/20 | 20/20 |
| 外部/腕部首帧哈希一致 | 0/20 | 仅报告 |
| 首动作哈希一致 | 0/20 | 仅报告 |

门禁因此失败。三个翻转模式分别为 `fail/fail/pass`、`pass/pass/fail` 和 `pass/fail/fail`。三个翻转案例在 224×224 模型输入中的像素差都稀疏且最大值为 1，但首动作与最终轨迹分歧。三轮共 5 次 `cube_outside_workspace_envelope` 安全中止；安全规则正常阻止了失控方块继续远离场景。

额外两次单 chunk 探针中，方块位置/姿态、腕部位置/姿态、腕部相机 eye/forward 六组数组全部逐位一致，仍出现 109/341 个模型输入差异像素和 `6.77e-4` 的首动作最大差，进一步定位到 RTX 渲染输出。显式 renderer accumulation reset 只在一次两运行探针中把差异降到 91/315 像素，仍未达到精确一致，不能升级为正式设置。
