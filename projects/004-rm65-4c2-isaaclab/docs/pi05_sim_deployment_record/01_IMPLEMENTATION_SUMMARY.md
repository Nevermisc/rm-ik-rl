# 已完成工作

## 1. 策略采样确定性

已将 pi0.5 策略服务的动作采样改为显式的、可复核的确定性流程：

- 服务端必须接收 `seed`；
- 使用 NumPy `float32` 高斯噪声，形状固定为 `(10, 32)`；
- 每个案例使用独立策略种子，并结合 chunk 索引派生采样；
- 服务端输出动作 SHA-256，客户端独立重新计算并校验；
- 已验证真实 v2 checkpoint 在交错请求和服务完整重启后动作逐位一致。

这解决了此前“同一个评测计划重复运行却得到不同动作”的关键阻塞。

## 2. 仿真侧种子与证据链

已统一设置 Python、NumPy、PyTorch/CUDA、Warp、Replicator 与 PhysX 相关随机种子，并将关键证据写入报告：

- 每个案例独立 `policy_seed` 与 `simulation_seed`；
- 每个动作 chunk 记录观测哈希与动作哈希；
- 恢复运行时校验 checkpoint、阈值、最大 chunk 数和种子配置；
- 正式评测最大动作 chunk 数统一为 120；
- 完整保存原始/安全处理后的夹爪目标序列。

仍存在一项已定位但未完全消除的非确定性：不同进程间 RTX 相机图像会出现少量像素差异。机器人初始状态和方块初始状态能够精确复现，因此问题已收敛到渲染路径，而不是物理初始状态或策略采样。

## 3. 渲染稳定性处理

已采用不会明显破坏策略输入分布的设置：

- 使用 FXAA；
- 关闭 DLSS 帧生成、深度学习降噪、运动模糊和 TV noise；
- 重置渲染器累积状态；
- 固定渲染 tick；
- 试验过多帧中值融合。

曾验证将图像强制降到 `80×60` 并做强量化可以获得更强的像素一致性，但该做法会显著改变训练/推理输入分布，已明确拒绝作为正式方案。

## 4. 闭环释放监督器

为解决“方块已经到达目标附近，但策略没有稳定松爪”的失败模式，实现了目标区释放监督器：

- 方块曾被成功抬起且进入目标中心 5 cm 范围后，锁存当前真实机械臂姿态；
- 目标区外执行每个 chunk 的前 5/10 个动作，目标区内保留全部 10 个夹爪动作；
- 策略夹爪目标需低于 `0.12`；
- 真实夹爪反馈需低于 `0.20`；
- 连续 2 个候选 chunk 后才触发，避免单帧误判；
- 触发后冻结机械臂、执行全开夹爪，并用 240 个物理步验证放置结果；
- 加入方块越过 1.0 m 工作空间包络时的安全中止。

该监督器的定位是“安全、可解释的执行层状态机”，并不改变 pi0.5 模型本身。

## 5. 评测结果演进

| 阶段 | 结果 | 用途 | 结论 |
|---|---:|---|---|
| 早期 v1 | 12/20（60%） | 历史基线 | 存在采样与复现问题 |
| 早期 v2 | 11/20（55%） | 历史基线 | 无法据此可靠比较 |
| 确定性基线 | 8/20（40%） | 正式改造前基线 | 释放失败突出 |
| 释放监督器开发集 | 12/20（60%） | 调试 | 监督器方向有效 |
| 开发计划 120 chunk | 17/20（85%） | 调参/诊断 | 不能当作独立正式结果 |
| 独立种子确认集 | **16/20（80%）** | 当前正式门槛 | 达到当前仿真门槛 |
| 预注册 60-case 鲁棒性计划 | **51/60（85%）** | 扩大样本验证 | 总体通过，外圈 panel 14/20 |

确认集使用策略种子 `280928000..280928019` 和仿真种子 `380928000..380928019`，与开发集无重叠。

60-case 计划使用策略种子 `490928000..490928059` 和仿真种子 `590928000..590928059`。所有报告齐全；4 个外圈案例在策略推理和机械臂运动前被连续 IK 安全检查拒绝，另有 5 个实际闭环失败。

## 6. 环境清理

发现旧容器 `libero-openpi_server-1` 长期占用约 8 GB 显存和 8000 端口。为避免与本次服务冲突，已安全停止但未删除；如需恢复，可执行：

```bash
docker start libero-openpi_server-1
```

本轮评测服务使用 8016 端口；评测结束后相关服务和 GPU 进程均已退出。
