# RM65-B + 4C2 + π0.5 项目学习记录与能力路线

更新时间：2026-09-24  
记录范围：从官方 π0.5 基线到当前 RM65 仿真闭环迭代  
真实性边界：截至当前没有控制真实机械臂

## 1. 项目目标如何逐步变清晰

最初目标是“在机械臂上部署 π0.5”。经过实践后，这句话被拆成可以验证的工程问题：

```text
基础设施是否能运行模型和仿真？
→ 参考机器人能否完成闭环任务？
→ RM65+4C2 资产是否具有正确关节、IK 和碰撞？
→ 任务在仿真中是否物理可完成？
→ 能否生成可靠专家数据？
→ 数据是否满足 OpenPI 契约？
→ π0.5 是否能在 16 GB GPU 上微调？
→ checkpoint 是否能输出安全动作？
→ 模型是否能在留出条件中闭环完成任务？
→ 评测本身是否可重复？
→ 达到门禁后才讨论真机。
```

这条拆解路线本身就是最重要的工程能力：把模糊目标变成逐层可证伪的实验。

## 2. 阶段时间线

### 阶段 A：Linux、SSH、NoMachine 与 Docker 入门

做过的事情：

- 理解 Linux 物理内存、GPU 显存和磁盘不是同一资源；
- 使用 `free -h`、`nvidia-smi`、`df -h` 检查资源；
- 通过 SSH 从 Windows 控制实验室 Linux；
- 使用 NoMachine 查看 Isaac Sim 图形界面；
- 理解 Docker 镜像、容器、挂载和 GPU 透传；
- 在容器中启动 π0.5 WebSocket 服务。

遇到的问题：

- JAX 首次编译很慢，WebSocket keepalive 误判超时；
- `nvidia-smi` 显示约 12 GB 是模型进程占用的显存，不是 Linux 系统内存；
- 终端 heredoc 粘贴不完整会导致 Python 代码错位。

学到的能力：

- 远程开发基本操作；
- 区分宿主机与容器；
- 用进程、端口和日志定位“程序没反应”；
- 先做模型 warm-up，再测稳态延迟。

### 阶段 B：官方/参考链路验证

做过的事情：

- 用 LIBERO 示例观测验证 π0.5 推理；
- 在 Franka IsaacLab 参考环境中完成严格闭环；
- 对三个场景做基线和鲁棒性矩阵。

结果：

```text
Franka 严格基线：9/9
Franka 鲁棒性：17/18
合计：26/27
```

学到的能力：

- 理解 benchmark、模型服务和仿真环境的关系；
- 用已知良好系统隔离基础设施问题；
- 理解“官方数据和官方机器人成功”只是基线，不等于自己的机器人成功。

### 阶段 C：RM65-B 与 4C2 资产迁移

做过的事情：

- 读取 RM65 与 4C2 URDF；
- 处理同名 `base_link`；
- 给 4C2 link/joint 加 `tool_` 前缀；
- 用固定关节连接 `link_6 → tool_base_link`；
- 将组合 URDF 导入 USD；
- 检查 articulation、joint、rigid body、collision 和 drive。

结果：

```text
16 links
15 URDF joints
12 movable joints
组合 IK 位置误差约 1.03e-6 m
12 个可达目标回归 12/12
```

学到的能力：

- URDF/XML 树结构；
- USD 与 URDF 的分工；
- articulation 与视觉模型的区别；
- 关节名称、顺序、限位和单位是控制接口的一部分。

### 阶段 D：夹爪接触物理与动作语义

做过的事情：

- 测量夹爪局部点随关节角变化；
- 确认 `0=张开、1=闭合`；
- 使用接触传感器区分基座碰撞与双侧指面接触；
- 为仿真加入独立接触垫；
- 做静态扰动、重力运输和开口校准。

关键失败：

- 原始 convex hull 虽然存在碰撞体，却没有形成有效双侧夹持；
- 只看峰值接触力会把瞬时碰撞误判为稳定抓取；
- `float64` 命令写入 `float32` 状态张量导致异常；
- 方块可能在高位开爪后卡在指间。

技术路线变化：

- 从“看画面像抓住”升级为双侧当前力、时间窗口均值、物体相对位移和释放后漂移；
- 从高位释放改为分段下降后自然释放；
- 夹爪阈值从任意常数升级为接触垫净空几何校准。

学到的能力：

- PhysX 接触诊断；
- 局部坐标到世界坐标变换；
- 碰撞代理与视觉 mesh 的区别；
- 物理通过标准应同时包含力、位移和稳定性。

### 阶段 E：脚本专家与完整任务

做过的事情：

- 使用 Lula IK 生成顶部抓取；
- 将任务拆成接近、闭合、抬升、转运、下降、开爪和撤离；
- 使用上一时刻解约束 IK 分支连续性；
- 修复底座高度、可达性边界和放置跟踪。

关键迭代：

1. 从直接初始化到抓取位，升级为动态接近；
2. 从关闭物体重力，升级为自然重力抓取；
3. 从辅助注入释放，升级为分段下降后的自然释放；
4. 从侧抓开发基线，升级为顶部抓取全重力完整任务；
5. 从 3 个演示角度，扩展到 45 个条件。

结果：

```text
顶部抓取全重力脚本专家：3/3
正式专家数据集：45/45
总帧数：20,175
```

学到的能力：

- 状态机设计；
- 笛卡尔轨迹与关节轨迹；
- IK warm start 和分支连续性；
- 任务成功指标与失败归因。

### 阶段 F：数据集工程

做过的事情：

- 定义每帧双图像、状态、动作、prompt、phase 和验证信息；
- 以 20 Hz 记录 240 Hz 仿真；
- 建立 5 转运角 × 3 x 偏移 × 3 y 偏移的 45 条计划；
- 固定划分 36 train / 9 validation；
- 支持中断后续跑和条件一致性检查；
- 转换为本地 LeRobot 数据集；
- 计算 RM65 专用 norm stats。

关键认识：

- 图像、状态和动作必须在同一时间语义下对齐；
- validation 必须在训练前固定，不能训练后挑选；
- 成功 episode 才能进入训练集；
- repo id 决定 OpenPI 使用哪份统计量。

学到的能力：

- 数据 schema 与 dtype/shape；
- episode、frame、timestamp 和 split；
- 数据质量校验；
- 可恢复批处理和可追溯实验设计。

### 阶段 G：π0.5 RM65 接口

做过的事情：

- 将 RM65 两幅图像、6 轴和夹爪状态映射到 OpenPI；
- 将真实 7 维 state/action 填充到模型内部 32 维；
- 前六轴训练为相对当前状态的 delta，夹爪保持绝对目标；
- 推理后还原为 6 个绝对关节目标和 1 个夹爪目标；
- 加入动作有限值、限位、最大步长与夹爪 clamp。

学到的能力：

- 模型接口适配比“改一个维度”复杂；
- action semantics 必须包含关节顺序、绝对/增量、单位和 horizon；
- 模型输出必须经过独立安全层。

### 阶段 H：16 GB GPU 上的 LoRA 微调

做过的事情：

- 构建 RM65 专用 π0.5 LoRA 配置；
- 用 2 步 smoke test 和 20 步 benchmark 评估显存；
- 处理 XLA OOM；
- 把 token 上限从 200 缩到 64；
- 冻结 SigLIP 视觉编码器；
- 训练 v1 与 v2 各 30,000 步；
- 记录 checkpoint、loss、gradient、parameter norm 和文件哈希。

v2 训练证据：

```text
loss：0.2278 → 0.0022
训练日志记录：300 个
最后 step：29900
全部数值有限
```

学到的能力：

- LoRA 与冻结策略；
- JAX/XLA 显存分析；
- smoke test、benchmark、正式训练的层级；
- checkpoint 与 norm stats 必须成对版本化。

### 阶段 I：离线验证与仿真闭环

做过的事情：

- checkpoint 单帧验证；
- 9 条 validation episode 的离线动作比较；
- WebSocket 策略服务；
- 每次预测 10 步、执行 5 步的滚动闭环；
- 20 条训练范围内的新条件评测；
- 逐案例失败分类与 v1/v2 对比。

结果：

```text
v1：12/20 = 60%
v2：11/20 = 55%
门槛：至少 16/20 = 80%
```

关键认识：

- 低离线动作误差不能证明任务成功；
- 数据视图更“密集”不一定提高闭环能力；
- 同义 prompt、动作时序、释放和目标精度都可能成为瓶颈；
- 分析报告 `status=pass` 可能只表示分析成功，模型门禁要看 `candidate_gate.passed`。

### 阶段 J：评测判据与可复现性审计

做过的事情：

- 发现最终夹爪状态会在已释放后因动力学回弹；
- 用接触垫几何把开爪阈值 0.20 校准为约 52.6 mm 净空；
- 把“最终夹爪值”改为“模型命令和实际反馈连续三轮验证释放”的设计；
- 用 16 条开发复测发现同一 checkpoint 的结果大幅翻转；
- 定位 OpenPI 默认 JAX RNG 与断点续跑顺序耦合。

当前结论：

- 16 条开发复测为 8/16，只用于诊断，不能替代正式评测；
- 每 case、每 chunk 的确定性噪声协议尚未完成验证；
- 在修复可重复性前，不应基于复测结果继续调模型。

学到的能力：

- 评测本身也要接受测试；
- 随机策略需要记录 seed 与采样哈希；
- 可恢复运行必须保持与完整运行相同的随机语义；
- 不能通过事后修改阈值“把失败改成成功”。

### 阶段 K：迁移到新 Ubuntu 24.04 电脑

做过的事情：

- 配置 SSH、Tailscale 和 NoMachine；
- 迁移项目、OpenPI、IsaacLab、Isaac Sim、Docker 镜像、checkpoint、数据和缓存；
- 安装 ROS2 Jazzy 工作区；
- 验证 RTX 4080 SUPER、Docker GPU、IsaacLab headless、RM65 articulation、IK、夹爪和 OpenPI 推理；
- 保留机器可读迁移审计。

结果：

```text
results/new_lab_pc_migration_audit.json：PASS
旧电脑不再是项目依赖
```

学到的能力：

- 迁移不是“复制项目文件夹”，还包括运行时、缓存、权重、数据、环境和验收；
- 每个大文件和关键能力要留下独立证据；
- 新机器验收应覆盖代码、GPU、容器、仿真和模型，而不仅是能 SSH。

## 4. 你还需要补哪些知识

### 4.1 代码能力优先级

1. Python：模块、类、类型标注、异常、日志、单元测试；
2. NumPy/PyTorch：广播、shape、dtype、device、序列数据；
3. Linux：shell、进程、端口、权限、环境变量和日志；
4. Git：小提交、分支、diff、冲突和回滚；
5. ROS2：node、topic、message、QoS、TF2、rosbag；
6. C++：等进入 RealMan 驱动与实时控制再加强。

### 4.2 数学与算法优先级

1. 线性代数：矩阵、坐标变换、特征值；
2. 三维旋转：欧拉角、旋转矩阵、四元数、SE(3)；
3. 机器人学：FK、Jacobian、IK、轨迹插值；
4. 概率：随机变量、分布、采样、seed 与统计置信度；
5. 优化：梯度下降、loss、正则化、LoRA；
6. 控制：PID、闭环、稳定性、频率、延迟与 watchdog；
7. 深度学习：Transformer、视觉编码器、行为克隆、flow matching。

### 4.3 LeetCode Hot 100 的作用

有帮助，但不是这个项目的主线。

它能提高：

- Python 熟练度；
- 数组、哈希、栈、队列、树和图；
- 复杂度分析；
- 面试表达。

它不能替代：

- 线性代数和坐标变换；
- NumPy/PyTorch 张量；
- Linux、Git、Docker；
- ROS2、仿真和机器人控制；
- 实验设计与可复现性。

建议时间比例：项目实践 60%，数学与机器人学 25%，LeetCode 15%。

## 5. 接下来四个学习里程碑

### 里程碑 1：你能讲清一帧数据

任务：从一个 episode 中打印图像 shape、7 维 state、7 维 action、phase 和时间戳，并解释它们如何对齐。

### 里程碑 2：你能讲清一次模型推理

任务：跟踪 `RM65Inputs → π0.5 → RM65Outputs → action_guard`，写出每一步 shape 和单位。

### 里程碑 3：你能修复并证明评测可重复

任务：实现 per-case/per-chunk seed，验证单例、完整运行和续跑的噪声哈希与动作一致。

### 里程碑 4：你能自己提出 v3 假设

任务：在确定性 20-case 结果上，只选择一个主要失败原因，提出数据或控制修改，预先写出指标，再训练和比较。

## 7. 学习记录的维护方法

每次实验追加下面的模板：

```markdown
### 日期 / 实验名称
- 假设：
- 唯一改动：
- 固定不变的条件：
- 命令：
- 输入证据：
- 输出报告：
- 结果：
- 失败分类：
- 我能证明什么：
- 我不能证明什么：
- 下一步：
```

只要坚持这种记录方式，你会逐渐从“会运行别人代码”转变为“能设计、验证和解释机器人学习实验”。
