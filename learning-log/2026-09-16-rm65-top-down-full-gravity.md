# 2026-09-16：RM65 顶部抓取与全重力完整任务

## 今天要解决的问题

昨天的脚本专家能完成抓取和放置，但 `link_6` 在抓取时低于源支撑面。普通桌面会挡住腕部，因此需要把抓取姿态改为从方块上方进入，并去掉机械臂和活动夹指的重力隔离。

## 先做了哪些失败实验

1. 根据已有侧抓姿态中“腕部到方块”的局部向量，构造严格顶部抓取姿态。
2. 扫描 yaw 为 0、±90°，Lula 均无解。
3. 把腕部到方块的方向从竖直方向倾斜 15°、30°、45°、60°、70°，仍无解。
4. 对严格顶部姿态使用 256 个确定性随机关节初值，仍无解，排除单一 warm start 问题。
5. 从原侧抓姿态连续插值到顶部姿态。0% 可达，5% 和 10% 的抓取位可达但竖直预抓取撤离很快失效，15% 起抓取位本身无解。

这些失败很有价值：它们说明问题不是简单换一个腕部 yaw，也不是 IK 求解器偶然落入错误分支。

## 根因

旧脚本把 RM65 基座放在世界 `z=0`，但源支撑顶面位于 `z=0.733 m`。严格顶部抓取要求 `link_6` 到达约 `z=0.873 m`，超过机械臂相对基座的工作范围。

侧抓基线可以工作，是因为腕部位于支撑面下方，只有夹爪向上/向侧面伸到方块。这也解释了宽桌面为什么会挡住旧轨迹。

## 修复

`run_pick_place_baseline.py` 新增 `--robot-base-z-m`：

- Isaac 场景中的机器人 root 按该高度生成；
- 方块和平台仍使用世界坐标；
- 送给 Lula 的目标位置减去机器人基座平移，转换到基座坐标；
- 报告同时保存机器人基座世界位置；
- 放置阶段的命令末端位置重新加上基座平移，避免混淆基座坐标和世界坐标。

使用 `--robot-base-z-m 0.65` 后，严格顶部 IK 由原始关节种子直接求解成功，10 个接近路点全部完成。闭合时左右二级指节峰值接触力约为 `3.245/3.187 N`，最近窗口均值约为 `0.984/0.999 N`。

## 完整任务结果

完整任务打开了 RM65、4C2 六个活动夹指和方块的重力，并执行：

1. 从 10 cm 外分 10 段接近；
2. 闭合夹爪；
3. 竖直抬升 40 mm；
4. 关节 1 转动 0.8 rad；
5. 分 12 段下降 120 mm；
6. 在宽平台上自然张开夹爪；
7. 沿下降路径反向撤离。

没有直接初始化到抓取位，没有跳过接近碰撞，没有关闭机械臂或夹指重力，没有向方块注入位姿或速度。结果：

| 指标 | 数值 |
|---|---:|
| 状态 | PASS |
| `unassisted_full_task_complete` | `true` |
| 方块实际抬升 | `39.568 mm` |
| 最终目标误差 | `17.557 mm` |
| 释放后漂移 | `1.242 mm` |
| 接近最大关节误差 | `0.01290 rad` |
| 抬升最大关节误差 | `0.01284 rad` |
| 放置最大关节误差 | `0.10519 rad` |

放置关节误差仍比接近和抬升大，需要在数据采集前继续调慢下降速度或改进重力补偿。当前夹爪的 `40×14×18 mm` 碰撞垫也是经验值，必须按实物尺寸校准。

## 鲁棒性复测与 IK 分支跳变

首次复测时，0.6 和 0.8 rad 通过，1.0 rad 在撤离阶段把方块带出平台。把每段下降时间从 60 步增加到 120 步后，结果反而更差，因此不是简单的动态滞后。

新增 `--diagnose-kinematics-only` 后发现：

- 0.6/0.8 rad 的最大相邻下降命令只有 `0.04031 rad`；
- 0.7 rad 最后一个路点的关节 3 从 `-1.619` 跳到 `+1.621 rad`；
- 1.0 rad 第四个路点的关节 5 从 `+1.774` 跳到 `-1.736 rad`。

这些姿态逐点看都满足 IK，但连起来不是可执行轨迹。由于整个放置方位只是绕基座 z 轴旋转，脚本现在先在未旋转方位求连续下降轨迹，再只给关节 1 加转运角。修复后 0.7/1.0 rad 的最大路点变化均为 `0.04031 rad`。

最终 0.6、0.8、1.0 rad 三次全部通过：最小抬升 `39.568 mm`，最大最终误差 `17.557 mm`，最大释放后漂移 `2.354 mm`。失败证据和修复前后路点仍保存在 `results/top_down_*failure*.json` 与 `results/top_down_kin_*.json`。

## 当前结论边界

这是 RM65 + 4C2 的脚本专家仿真闭环。它证明了场景几何、顶部接近、抓持、运输、碰撞放置和自然释放可以连起来。它没有使用 π0.5，也没有向真实机器人发送任何命令。

机器可读单次证据：`projects/004-rm65-4c2-isaaclab/results/top_down_full_gravity_0p8.json`。
